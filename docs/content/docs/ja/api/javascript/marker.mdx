```ts
export type marker = (id: string, pseudo: string) => Marker;
export const marker: marker;

export type extended = <I extends string, P extends string>(id: I, pseudo: P) => Extended<I, P>;
export const extended: extended;
```

`marker` と `extended` はペアです：子要素はコンビネーターを使用せず、それらの間のパスを名付けずに祖先の状態に応答します。スタイルは **原子的** に保たれます。

<Callout type="info">
  **生産準備完了。** これらのAPIは、現在のバージョンであるChrome、Edge、Safari、FirefoxがすべてサポートしているCSSコンテナスタイルクエリ（`@container style()`）にコンパイルされます。
</Callout>

- **`marker(id, pseudo)`** - 親要素にCSS変数のマーカーを設定します。
- **`extended(id, pseudo)`** - マークヤーがアクティブなときに、子要素にスタイルを適用します。

### 引数 [#parameters]
両方の呼び出しは同じ2つの引数を持ち、一致するとペアがリンクされます。
- **`id`** - マークと拡張スタイルをリンクするユニークな識別子
- **`pseudo`** - 疑似クラスの状態（例：`':hover'`, `':focus'`, `':active'`）

## 仕組み [#how-it-works]

### 内部の動き [#internal]

**`marker()`**は、擬似クラスがアクティブになっているときにCSS変数を生成します：
   ```css
   .parent:hover {
     --xyuz5mma-ul-hover: 1;
   }
   ```

**`extended()`**は子スタイルをコンテナクエリにラップします：
   ```css
   @container style(--xyuz5mma-ul-hover: 1) {
     .child { /* styles */ }
   }
   ```

CSS変数は、マークアップのどこに配置されていても、すべての子要素が継承する**信号**です。

<Callout title="ESLint のルール">
  `no-combinator`ルールは、コンビナタール構文を許可しないことでこのパターンを強制します。
</Callout>

## 関数形式の疑似クラス [#functional-pseudo-classes]

機能的なものを含む、任意の偽クラスが受け入れられます。

```ts
const styles = css.create({
  wrap: {
    ...css.marker('wrap', ':has(a:hover)'),
  },
  child: {
    [css.extended('wrap', ':has(a:hover)')]: { color: 'red' },
  },
});
```

```css
.xwpr9f08:has(a:hover) {
  --xg204awn-wrap-has: 1;
}

@container style(--xg204awn-wrap-has: 1) {
  .xof70rr5:not(#\#) {
    color: red;
  }
}
```

`:has()` はマーカーの移動方向を反転させます：状態は子要素に属し、マーカーはそれを含む要素に配置され、スタイルはその要素の任意の子要素に配置されます。CSSでは同じ関係を `.a:has(.b:hover) .c` と表現し、3つの要素間のパスを名付けますが、マーカーはそれらのいずれにも名前を付けません。

`:defined`はすべての標準要素に一致するため、マーカーを永続的なシグナルに変換します。つまり、状態を伴わない単純な子孫関係です。

<Callout type="warn" title="祖先の要素にマーカーを置く">
  `extended` スタイルは、マークされた要素の下にある要素に適用され、それ以外には適用されません。そのサブツリーの外に同じコンポーネントをレンダリングすると、スタイルは単に欠如します — エラーも警告もありません、なぜならクエリに一致するものがないからです。`:hover` のようなステートでは「ステートは一度もトリガーされなかった」と読み取られ、常に有効な `:defined` では、スタイルが消えたと読み取られます。
</Callout>

## すべての結合子を表す [#every-combinator-expressed]

| CSS | Plumeria |
| :-- | :------- |
| `.a .b` — 状態上の子孫 | `css.marker(id, ':hover')` + `css.extended` |
| `.a .b` — 派生子、状態なし | `css.marker(id, ':defined')` + `css.extended` |
| `.a > .b` — 子 | `css.marker(id, ':defined')` + `css.extended` を子要素に |
| `.a + .b`, `.a ~ .b` — 兄弟 | `css.marker(id, ':defined')` + `css.extended` を親族に |
| `.a:hover ~ .b` — ステータスに反応する親族 | `css.marker(id, ':has(a:hover)')` + `css.extended` |
| `.a:has(.b) .c` — 子孫の状態、上下をまたいでバックアップする | `css.marker(id, ':has(input:focus)')` + `css.extended` |

マーカーは、両方が共有する要素に適用されます。子供の場合、それは親であり、兄弟の場合、共通の親です。子供と兄弟を区別するものはセレクターではなく、あなたが`extended`をどの要素に渡すかです。

CSSの列名はパスを名付けますが、Plumeriaの列名は付けません。`marker`と`extended`はIDでリンクされているため、スタイルは任意の深さのすべての子要素に到達し、要素をさらに深くに移動してもペアが無効になることはありません。

**まず `marker` / `extended` を取得してください。** その代替手段はセレクターキーです。これは、`no-combinator` が許可する、機能的な擬似クラス内のコンビナタであり、あなたが自分で指定した要素に付着しています：

```ts
const styles = css.create({
  cell: { ':is([data-row] > *)': { color: 'red' } },
});
```

それはパスを名付けているため、要素を移動するとそれを壊し、各宣言ごとにセレクター全体が繰り返されます。マーカーペアはパスを名付けておらず、idを共有するすべての`extended`は一つの`@container`ブロックに配置されます。

| 1つの関係の下のターゲット | セレクターキー | `marker` / `extended` |
| -------------------------: | -----------: | --------------------: |
| 1 | 94 B | 147 B |
| 5 | 281 B | **43 B** |

<sub>同じマークアップを Vite の本番ビルドで測り、それぞれの方法で増えた CSS のバイト数を比べました。</sub>



セレクターキーはエスケープハッチです。ターゲットがマークアップされている場合、書き込まないためスタイルを添付できません。

### コンテナクエリのコスト [#what-the-container-query-costs]

`extended`はスタイルクエリにコンパイルされ、状態が変更されたときにエンジンがコンテナごとに再評価します。ヘッドレスChromiumでのクラストグルを測定したスタイル再計算、30回の実行のメディアン値：

| 要素 | シンプルなCSS | セレクターキー | `marker` / `extended` |
| -------: | --------: | -----------: | --------------------: |
| 500 | 0.009 ms | 0.006 ms | 0.012 ms |
| 2,000 | 0.008 ms | 0.007 ms | 0.012 ms |
| 8,000 | 0.005 ms | 0.005 ms | 0.012 ms |

<sub>一回の測定で切り替えたのは、ホバーやフォーカスの対象になる一つの要素です。その要素までの経路にあるコンテナーだけが再評価されるため、ページ全体の要素が増えても時間はほぼ一定です。</sub>



コストはページ数とともに増加しません。**すべての**アンカーを同時に切り替える場合、コストは増加します：8,000回の同時切り替えはセレクターキーの7msに対して26msかかります。これは形状ユーザーインターフェースが採用する形ではありませんが、もし探してみると違いが生じるのはそこです。
