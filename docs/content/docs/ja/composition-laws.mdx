`sx` の配列はプロパティごとにスタイルを重ねます。右のスタイルを左に重ねる操作を $\oplus$ と書くと、次の四つの規則があります。スタイルを別の場所に移したり、まとめ直したりするときにも使える規則です。

## 結合法則 [#associativity]

$$(A \oplus B) \oplus C = A \oplus (B \oplus C)$$

配列をどこでまとめるかは結果に影響しません。配列は入れ子にできるので、次の二通りは同じです。

```tsx
<div sx={[[styles.a, styles.b], styles.c]} />
<div sx={[styles.a, [styles.b, styles.c]]} />
```

そのため、配列の一部を変数や prop に取り出しても、同じ位置に戻せば結果は変わりません。

## 単位元 [#identity]

$$A \oplus I = I \oplus A = A$$

`false`、`null`、`undefined` を重ねても何も変わりません。これらは単位元 $I$ として働きます。配列に条件式を書けるのもこのためです。

```tsx
<div sx={[styles.base, isActive && styles.active]} />
```

`isActive` が偽なら、残るのは `styles.base` だけです。

## 冪等性 [#idempotency]

$$A \oplus A = A$$

同じスタイルを自分自身に重ねても結果は同じです。共通の基本スタイルと prop の両方を通って同じスタイルが届いても問題ありません。

## 交換法則は成り立たない [#no-commutativity]

$$A \oplus B \neq B \oplus A$$

順番には意味があります。同じプロパティを指定した場合は右側の値が残るので、二つのスタイルを入れ替えると結果も入れ替わります。指定するプロパティが違えば競合せず、順番を変えても同じです。

一括指定と個別指定が重なる場合は例外です。どちらを先に書いても個別指定が優先されます。[スタイルの優先順位](/ja/docs/specificity)

## マージは monoid [#the-merge-is-a-monoid]

モノイドは、対象が一つだけの圏として表せます。各スタイルはその対象から自分自身に戻る矢印です。配列は複数の矢印を一つに合成し、`false` は恒等射、つまり何も変えない矢印に当たります。

<img src="/one-object-category.svg" width={1000} height={380} alt="一つの対象に戻る矢印でスタイル a と b を表す。配列は矢印を合成し、false は恒等射になる。結果は一つのクラス一覧になる" />

まとめ方を変えても結果が同じで、何も変えない値もあるため、この演算は**モノイド**になります。配列をどのように入れ子にしても、途中に条件があっても、一つのスタイルにまとめられます。コンパイラはこれをビルド時に行い、要素には一つのクラス一覧を渡します。

$$parse(A \oplus B \oplus C) \to \text{"classA classB classC"}$$

ここでいう `classA` などは、各スタイルのクラス名をそのまま並べたものではありません。右側の指定で上書きされた値のクラスは除かれます。

```tsx
const styles = css.create({
  a: { color: 'red', padding: 4 },
  b: { color: 'blue' },
});

<div sx={[styles.a, styles.b]} />
```

この要素には `padding: 4px` と `color: blue` の二つのクラスが付きます。`color: red` のクラスは付きません。同じプロパティに対する二つのクラスが要素上で競合しないので、CSS のカスケードに結果を委ねずに済みます。
